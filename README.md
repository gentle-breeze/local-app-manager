# Local App Manager · 应用观测台

面向本机应用的生命周期管理器与运行看板。既能只读观察已有服务，也能对明确登记的前台程序执行启动、停止和重启；帮助查看端口、HTTP 可访问性、进程指标和最近日志。Python 标准库后端，原生 HTML/CSS/JavaScript 前端，无第三方运行依赖。

## 快速开始

需要 Python 3.9 或更新版本及 POSIX 进程组支持（macOS / Linux）。本次生命周期回归在 Linux 验证；未验证 macOS 特有行为。监听进程身份与指标探测仍使用 macOS 的 `/usr/sbin/lsof` 路径，Linux 上缺少该命令时显示“未知”，不影响受管生命周期。

```sh
git clone https://github.com/gentle-breeze/local-app-manager.git
cd local-app-manager
python3 server.py
```

打开 **http://127.0.0.1:4320**。按 `Ctrl+C` 退出。可用 `--port 4321` 改端口；监听地址始终是 IPv4 loopback。请使用明确的 `127.0.0.1` 地址，不支持代理、公开部署或远程访问。

初次启动为空白看板。点击「添加应用」，填写名称和本机端口即可只读观察已有服务，无需修改代码。可选填写工作目录、HTTP 健康检查路径、明确指定的 `.log` 文件。端口 0 表示不探测。

## 状态如何解读

- 每 5 秒刷新。端口可达只表示 TCP 连接成功；HTTP 成功只表示入口可访问，业务健康仍标为未知。
- 未发现监听不代表应用已停止：它可能使用其他端口、非 TCP 通信或在另一台机器上运行。
- 只有监听进程工作目录与登记目录一致才展示 PID、运行时长、CPU 与 RSS 内存。这是单个监听进程的数据，不是整棵进程树。CPU 使用系统 `ps` 值，不是固定采样窗口的即时占用。
- 日志只显示明确指定文件的最后 16 KB，或本管理器启动进程的有限内存输出。没有日志不代表没有异常。日志弹窗是打开时的快照，重新打开可查看新内容。
- 受管条目另显示“正在运行 / 正在停止 / 停止超时 / 已确认停止”等生命周期状态，与端口探测结果分开；超时不代表已经停止。
- 设置中可修改目录、端口、HTTP 路径、日志路径和停止策略。观察/受管模式创建后不能转换；需要受管时另建条目。第一版不提供删除条目、远程应用监控或自动扫描所有进程。

## 可选进程管理

添加应用时展开高级设置，允许管理器启动应用，填写工作目录和命令 JSON 数组。首项必须是可执行文件绝对路径，例如 `["/usr/bin/python3", "app.py"]`。程序以前台方式执行，不经 shell 解释。仅登记可信程序，不要在参数中填写密钥。

已有观察条目不允许启停。受管操作只作用于本管理器创建的子进程，不接管已存在进程；端口被占用时拒绝启动。对于端口 0 的应用，无法检测已有副本。

每个受管应用有独立 supervisor 和进程组。停止与重启遵循：**发送信号 → 等待实际退出 → 超时按策略处理 → 确认整个受管进程组停止后，才允许再次启动**。不再固定等待 1 秒后无条件强杀。

在高级设置中可配置（已有配置未填写时使用默认值）：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `stop_signal` | `SIGTERM` | 首次停止信号，可选 `SIGTERM` / `SIGINT` |
| `stop_timeout` | `10` | 优雅退出等待秒数，范围 0–3600，可为小数 |
| `stop_policy` | `kill` | `kill`：超时后发送 `SIGKILL`，仍需确认退出；`wait`：超时报告错误，继续观察而不强杀 |

优雅退出若提前完成，会立即继续，不必等满超时时间。`wait` 策略超时后仍保留运行句柄和停止状态，不会创建替代实例；可再次点击停止或重启，等待另一个配置时限。只有实际退出被确认后，重启请求才会创建新实例。同一应用的重复或并发操作不会绕过这一检查。

应用自然退出后会按同样策略处理组内残留子进程。管理器退出或控制管道断开也遵循配置的停止策略：**`wait` 不承诺退出管理器时杀掉应用**，未退出的进程会继续由 supervisor 等待，并保留该数据目录的实例锁，因此实际停止前无法用同一数据目录启动另一个管理器。若需要超时后强制清理，请选择 `kill`。

使用内存中的子进程句柄，不持久化 PID，也不根据历史 PID 发送信号。停止状态无法确认时拒绝启动；端口关闭本身不是退出凭据。监管进程在独立进程组外等待；保留未回收的组长 PID，确认组内没有存活成员后才回收，避免向重用的进程组发送信号。强杀后若 5 秒内仍不能核实退出，会报告错误并保留监管，不启动替代实例。不支持自行 `setsid` 或脱离进程组的守护程序，请勿登记后台服务安装命令。

同一数据目录使用内核文件锁防止重复实例。默认配置保存在被 Git 忽略的 `.local/apps.json`，可通过 `--data-dir` 指定独立数据目录。

### 监管异常后的恢复

启动前会在数据目录的 `unconfirmed/` 下写入该条目的运行代次标记，仅含 `app_id` 与随机 `generation`，**不存 PID，也不用于发送信号**。只有 supervisor 核实整组退出后才删除标记。若 supervisor 崩溃或退出确认丢失，标记会保留：关闭并重开管理器也不会绕过它，此条目继续显示“未确认停止”，启动、停止和重启均被拒绝；其他没有未确认标记的条目仍可使用。

恢复需要人工核实，而不是直接重启管理器：

1. 在应用自己的终端或系统进程工具中，核实该应用及其子进程均已退出；端口不再监听并不足以证明退出。不要根据旧 PID 盲目发送信号。
2. 退出管理器，在 `apps.json` 中找到对应条目的 `id`，再找到 `unconfirmed/` 中 `app_id` 相同的标记。
3. **仅在退出已经核实后**删除这一条标记（不要清空整个目录），再启动管理器。无法核实时保留标记，不启动替代实例。

应用自行脱离受管进程组不在这个保证范围内；运行代次标记也不是进程恢复或接管机制。


## 安全与限制

- 仅监听 loopback；不安装开机服务、不改防火墙、不创建长期凭据。
- HTTP 验证 Host；写请求要求匹配的 Origin、JSON 类型和每次启动随机会话令牌。不启用 CORS；CSP 限制外部资源与嵌入。
- 子进程仅继承 `HOME/PATH/LANG/TMPDIR`。应用可自行读取其既有安全配置，管理器不扫描环境文件或读取进程环境。
- 日志敏感行过滤属于启发式处理，不能保证发现所有秘密。不要登记含密钥的日志或将密钥写入命令。输出不另存磁盘；内存缓存最多 160 块，每块最多 2048 字节。
- 本机同账户程序和浏览器属于信任边界。本工具不是多用户权限隔离系统，也不应通过隧道或代理暴露。
- 仓库不包含实际应用登记、运行结果、截图或个人机器信息。测试生成的 `evidence/` 默认忽略，可能含本机临时路径，请不要公开提交。

## 构建和测试

```sh
python3 -m unittest discover -v -p 'test_*.py'
python3 build.py
# 可选前端语法检查，需要 Node.js
node --check web/app.js
node test_ui.mjs  # 无浏览器的表单与生命周期显示回归
```

构建产生独立 `dist/`，可用 `python3 dist/server.py` 启动。其默认数据目录为 `dist/.local`；需要共享配置时显式指定 `--data-dir`。

集成测试使用临时目录和 loopback 合成服务，覆盖生命周期、慢速优雅退出、超时策略、重复与并发操作、确认停止后重启、重复实例、外部端口不接管、进程组清理、父管道断开、日志边界和 HTTP 请求防护。无需连接个人电脑或真实应用。

可选无头浏览器验收需要 Node.js 22+ 和已安装的 macOS Google Chrome，不会自动下载软件：

```sh
node test_headless.mjs
```

测试使用独立临时 Chrome profile、空白临时登记和专用测试服务，覆盖宽屏/窄屏、添加/取消/重复保存、状态区别、日志显示与脱敏、受管进程启停和 JavaScript 异常检查。结束后清理临时实例与 profile；结果及截图保存在被忽略的 `evidence/`。不会连接桌面 Chrome 个人资料。无头测试不等于桌面浏览器验收。

仓库目前未配置 CI 工作流；请按上述命令在支持的本机环境验证。

## 按项目拉取 GitHub 配置分支后部署

每个**受管应用**的高级设置可独立填写 `github_url`，格式为 `https://github.com/owner/repo`（可带 `.git`）；不填写时仍使用原来的本地启停方式。地址与 `github_branch` 分支均存于该应用条目，不硬编码项目仓库或部署分支。`github_branch` 未配置或留空时默认 `main`，兼容旧配置；例如可为 `develop`、`release/stable`，不同项目可使用不同分支。分支只支持 1–200 个 ASCII 字母、数字、`_`、`-`、`.`、`/`，首字符须为字母、数字或 `_`；不支持空白、`..`、空路径段、以点开头的路径段、`.lock` 路径段后缀或末尾点，不接受 refspec/标签/提交表达式。只支持公开 GitHub HTTPS 仓库：匿名拉取，不使用既有 Git 凭据、SSH、全局 URL 重写或 hooks；不支持私库、重定向、子模块和 Git LFS 下载。

配置后，启动或重启都会直接拉取该地址的 `refs/heads/<github_branch>`，而不是本地分支、工作树或本地 `origin`。即使登记目录的 origin 不同，也以**这一条目明确配置的地址**为准。配置分支不存在、网络失败等会明确报错，不退回本地旧代码。

流程：**独立 release 目录拉取 → 可选构建 → 可行的启动文件检查 → 停止旧进程并确认整组退出 → 从新 release 启动**。准备失败不停止正在运行的旧服务；重启超时仍遵循停止策略，绝不创建第二个实例。同一条目的操作和配置保存互斥，不同项目使用不同 release。

- `build_argv` 为可选构建命令 JSON 数组，首项为可执行绝对路径，无 shell。例如 `["/usr/bin/python3", "build.py"]`（示例而非默认）。在新 release 内执行；请在这里明确安装依赖、构建并执行必要的验证。Git 单步最长 300 秒，构建最长 600 秒；超时或遗留同组子进程会被清理并拒绝部署。构建必须以前台方式执行，不得脱离进程组；本工具不是代码沙箱，仅登记可信仓库和命令。输出只在内存保留有界片段，不把构建日志写到磁盘或暴露给 API。
- 原有 `argv` 仍是启动命令。相对文件参数从 release 解析；指向登记工作目录内的绝对脚本、虚拟环境可执行文件等会映射到 release 对应位置（包括目录符号链接别名）。外部绝对可执行文件不变；必须自行确认使用的是可信解释器，而非另一份旧应用。内嵌本地路径（如 `--config=/原项目/...`）、越界路径不支持，请改用独立参数或 release 内相对路径。命令文本或程序内部硬编码路径无法自动迁移。
- **不会复制本地未提交代码、`.env`、未跟踪文件、虚拟环境、`node_modules` 或可变业务数据**；本地目录、分支、索引均不改动。请在构建步骤重建依赖，并通过项目自身支持的外部绝对配置/数据路径接入持久资源。不要把需保留的数据写到 release。启动前检查只能发现一部分缺失文件，不能证明业务或依赖健康。
- 看板展示准备阶段、错误、最近启动版本的 commit 和目录。`launched` 仅表示 supervisor 报告已创建运行进程，**不表示应用就绪或健康**；随后立即退出会单独显示。新版本启动失败后不会自动回滚；旧服务此时可能已停止，需查日志、修正配置或远程代码后重试。不会用端口可达冒充退出/就绪凭据。
- 已启动的 release 保留在数据目录 `releases/` 下，避免删除仍在运行的代码，也可人工核查历史版本；失败且确认清理的准备目录会删除。没有自动清理或回滚按钮；只有人工确认相关进程均已退出后才可删除旧 release。准备前另写入 `unconfirmed-preparations/` 标记（只含 app_id，不含 PID）；清理无法核实或管理器异常退出时保留目录和标记，后续启动/重启均被阻止，停止旧实例仍可执行。人工确认该条目所有准备进程已退出后，关闭管理器并删除对应 app_id 的这一标记才能重试，不要按历史 PID 盲目发信号或清空整个目录。管理器正常重开后会再次按配置拉取，不自动复用历史 release。进程组验证基于现有 POSIX 监管能力；本次新增流程仅在 Linux 做了回归。

新增测试使用两个独立本地 Git fixture，通过测试传输注入替代网络；生产配置验证不允许本地/file URL。覆盖实际执行远端配置分支新版本（含斜杠分支名、旧配置默认 main）、脏工作树/不匹配 origin 保持原样、项目隔离、拉取/构建失败保留旧实例、超时清理、并发操作和退出屏障。不涉及真实项目部署或个人凭据。
